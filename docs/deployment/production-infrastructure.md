# Production Infrastructure

This is the provider-neutral infrastructure target for LevelUpX production.

## Services

- Backend API service built from `backend/`.
- Frontend web service built from `frontend/`.
- Managed PostgreSQL database.
- Optional managed Redis service.
- Hosted scheduler entries generated by `npm run jobs:schedule`.
- Private Prometheus-compatible scraper authenticated to the protected
  `/metrics` endpoint when enabled.
- Grafana dashboards and Alertmanager routing backed by that Prometheus
  instance.
- Sentry project or compatible error-tracking project when enabled.

## Deployment Pipeline

The GitHub Actions deployment workflow is `.github/workflows/deploy.yml`.

It does four things:

- validates environment variables and secrets with `scripts/validate-deployment-env.mjs`
- builds the backend and frontend
- validates the Prisma schema
- optionally triggers backend and frontend deploy hooks

Use the `production` GitHub environment for production secrets and variables. Keep deploy hooks disabled until the target hosting platform has backend and frontend services ready to receive them.

## Secret Manager

Store secret values in the hosting platform secret manager and mirror the same names in the GitHub `production` environment when the deploy workflow needs them.

Secrets:

- `DATABASE_URL`
- `JWT_ACCESS_SECRET`
- `JWT_REFRESH_SECRET`
- `WEEKLY_REPORT_RECIPIENT_EMAILS`
- `WEEKLY_REPORT_SMTP_HOST`
- `WEEKLY_REPORT_SMTP_USERNAME`
- `WEEKLY_REPORT_SMTP_PASSWORD`
- `WEEKLY_REPORT_API_ENDPOINT`
- `WEEKLY_REPORT_API_KEY`
- `AI_INSIGHT_ENDPOINT`
- `AI_INSIGHT_API_KEY`
- `PUSH_VAPID_PUBLIC_KEY`
- `PUSH_VAPID_PRIVATE_KEY`
- `REDIS_URL`
- `ERROR_TRACKING_DSN`
- `METRICS_AUTH_TOKEN`
- `BACKEND_DEPLOY_HOOK_URL`
- `FRONTEND_DEPLOY_HOOK_URL`

Non-secret runtime variables can live as GitHub environment variables and hosting platform config variables.
That includes the backend-visible `PROMETHEUS_URL` and optional operator links
`PROMETHEUS_PUBLIC_URL`, `GRAFANA_PUBLIC_URL`, and
`ALERTMANAGER_PUBLIC_URL`. Keep Prometheus private even when an authenticated
Grafana URL is exposed to operators.

## Provisioning Order

1. Provision managed PostgreSQL.
2. Create backend and frontend services.
3. Configure backend environment variables and secrets.
4. Configure frontend public runtime variables.
5. Provision Redis if `REDIS_ENABLED=true`.
6. Configure error tracking plus private Prometheus, authenticated Grafana,
   Alertmanager, and a real on-call receiver if monitoring is enabled.
7. Run `npm run prisma:deploy` against production.
8. Start the backend service.
9. Start the frontend service.
10. Install hosted scheduler entries from `npm run jobs:schedule`.
11. Run the deployment workflow with deploy hooks enabled.

## Release Checks

- `GET /api/health` returns `status: "ok"`.
- Health readiness reports `database: "configured"`.
- Health readiness reports the expected Redis status.
- Unauthenticated `GET /metrics` returns `401` when metrics are enabled.
- Prometheus can authenticate to `/metrics` and reports the backend target as
  up.
- The provisioned dashboard receives request, error, and latency history, and
  a controlled alert reaches the configured on-call receiver.
- Frontend can call `NEXT_PUBLIC_API_URL`.
- Socket.IO connects through `NEXT_PUBLIC_REALTIME_URL`.
- Scheduled jobs are installed exactly once per environment.
